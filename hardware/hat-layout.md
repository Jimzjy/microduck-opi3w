## 网络命名规范（2026-10-25 统一）

原工程网络名混着 SoC 侧信号名（`GPIO14_UART_TX`、`GPIO02_I2C_SDA`、`GPIO18_PCM_CLK`…），换到 A733 后这些名字全是误导。
现状一律按「HAT 板内功能」命名，SoC 管脚映射只写在 pinmap.md：

| 类别 | 网络名 |
|---|---|
| 电源 | `5V_VIN`（端子进）→ `Q2` 反接保护 → `5V_PF` → `F1` → `5V`（SoC/偏置）/ `F2` → `5V_A`（功放）；`3V3`、`1V8`、`GND` |
| I2C | `I2C_SDA`、`I2C_SCL` |
| DXL UART | `UART2_TX`、`UART2_RX` |
| I2S | `I2S0_BCLK`、`I2S0_LRCK`、`I2S0_DIN`（SoC 收）、`I2S0_DOUT`（SoC 发）、`AUDIO_MCLK` |
| codec | `CODEC_RESET_N`、`CODEC_RIGHT_LOP`、`MIC_EXT_L_AC`、`MIC_EXT_L_BIAS`、`MIC_EXT_R_AC`、`MIC_EXT_R_BIAS` |
| 功放 | `AMP_INR_AC`、`AMP_INR`、`AMP_VREF`、`AMP_VDD_FILT`、`AMP_R_P_RAW`、`AMP_R_N_RAW`、`SPK_R_P`、`SPK_R_N` |
| 舵机总线 | `DXL_DATA`、`DXL_DATA_CLAMPED`、`DXL_DIR`、`DXL_DIR_B`、`SERVO_VPASS` |
| 其他 | `RX_LED_ANODE` |

## J4 = 零位错位排母（详见 pinmap.md）

**2026-10-25 REV B 改线（A733 适配）**：DXL 总线的 UART 从「排针 8/10」挪到「排针 11/13」，走 A733 的 uart2（PB0/PB1），
console（uart0/ttyS0）继续留在 8/10 不动。落地方式（已改在原理图里，网表实测）：

| 目的 | J4 焊盘 | 排针脚 | 网络 |
|---|---|---|---|
| 新：SoC TX → HAT TX 缓冲 | J4-12 | 11 | `UART2_TX` = J4-12 / R26-1 / R27-1 / U7-2 |
| 新：HAT RX → SoC RX | J4-14 | 13 | `UART2_RX` = J4-14 / U6-4 / R31-2 / R34-1 |
| 旧连接已断开 | J4-7 / J4-9 | 8 / 10 | 悬空（留作 console 调试点） |

只跳线不切断是不行的——8/10 焊死在 J4 上，不切断等于 console 和 DXL 两个 UART 顶在同一个网。

## 功能分区（按原理图坐标，单位 0.01in，2026-10-25 排版后）

### ① 左上：J4 排母 + ToF + I2C 上拉
- J4(280,785) FH-00339 2×20P 排母，bottom 面
- **H1(695,705) = ToF 接口**（用户把原 J5 的 JST-SH 4P 座换成 1×4P 2.54 直插排针，
  XFCN PZ254V-11-04P，LCSC C2691448，针高 6.1mm）。**非 Qwiic 标准脚序，接线前必看**：

  | H1 脚 | 网络 | 说明 |
  |---|---|---|
  | 1 | `3V3` | 电源 |
  | 2 | `GND` | 地 |
  | 3 | `I2C_SCL` | SCL |
  | 4 | `I2C_SDA` | SDA |

  ⚠️ 原 J5（JST-SH 4P）是 Qwiic 标准序 1=GND / 2=3V3 / 3=SDA / 4=SCL，H1 把电源两根和 SDA/SCL 都换了位置。
  **只能用杜邦线按编号逐根接模块的 PTH，禁止插现成的 Qwiic 4 芯转接线**（会把 3V3/GND 反接到 VL53L5CX 上）。
  模块侧（VL53L5X V2）PTH 丝印为 GND / 3V3 / SDA / SCL。
- **R12(610,780) / R13(615,830) = 4.7k 上拉**（0603，LCSC C23162），`3V3` ↔ `I2C_SDA` / `I2C_SCL`。
  原图是 10k，400kHz 下 10k 的上升时间偏长（~300ns 级），已按 kissqy 实际做法改成 4.7k（≈200ns，仍满足 AIC3104/ToF 的低电平灌电流）。
- ToF 默认地址 0x29，与 codec 0x18 共用 I2C3。

### ② 左中：DXL 半双工方向切换与收发
- R26(220,1395) 10k `3V3`→`UART2_TX` 上拉；R27(220,1495) 10k + Q1(410,1395) MMBT3906 + R28(660,1505) 20k：方向控制
  - 网表：`UART2_TX` = J4-12 / R26-1 / R27-1 / U7-2；`DXL_DIR_B` = R27-2 / Q1-1；`DXL_DIR` = Q1-3 / R28-2 / U7-1(OE) / U6-1(OE)
- U7(685,1410) SN74LVC1G126 TX 缓冲（LCSC C7834）：A←`UART2_TX`，Y→`DXL_DATA_CLAMPED`，OE=`DXL_DIR`
- U6(895,1410) SN74LVC1G125 RX 缓冲（LCSC C3040625）：A←`DXL_DATA_CLAMPED`，Y→`UART2_RX`，OE=`DXL_DIR`
- R31(465,1235) 10k `UART2_RX` 上拉；R32(460,1295) 10k `DXL_DATA_CLAMPED` 上拉；D4(795,1235) 5.1V 钳位（C151348）
- C17(985,1510) 100nF / U6、C18(840,1510) 100nF / U7 去耦
- **U5（74LVC1G08 与门）+ R29（10k）+ C16（100nF）已于 2026-10-25 删除**：`RX_GATE_EN` 只接 R29 下拉、
  没有任何 GPIO 驱动，与门 B 恒为 0 → Y 恒为 0，`UART2_RX` 被永久拉低（等于收不到任何数据，是死逻辑）。
  删掉后 U6 的三态输出直接接 SoC，空闲时靠 R31 拉到高电平，收到数据正常翻转。
  （网表实测：`RX_GATE_EN` 网络已消失；`UART2_RX` = J4-14 / U6-4 / R31-2 / R34-1）

### ③ 中上：电源（外部 5V 输入）
- **拆除板载 DC-DC 与理想二极管链**（U9 AP63205、L4 6.8µH/3A、C20 自举、Q2 SI2312、U10 LM5050-1、
  R8 100R、C39 100nF 全部删除），5V 改为外部输入。
- **U11(280,235) 2P 螺钉端子 KF301-5.0-2P（C474881）**：pin1 → `5V_VIN`，pin2 → GND。
- **Q2(120,240) AO3401A P-MOS 反接保护**（SOT-23，C15127）：D(3)→`5V_VIN`，S(2)→`5V_PF`，G(1)→`Q2_G`；
  R36(120,350) 10k 把栅极常态拉到 GND（`Q2_G` = Q2-1 / R36-1，R36-2 → GND）。
  正向：Vgs=−5V → 导通，Rdson≈60mΩ（2A 时压降 ~0.12V）；**反接**：体二极管反偏 + Vgs=0 → 全断，
  下游完全断电，电流不流进 D1/F1，也不会像无保护时那样靠 D1 正偏去“撬”保险丝。
  代价：栅极没有稳压管钳位，只适合 5V 输入；若以后接 12V，需在 G-S 间加 5.1V 齐纳（如板上 D4 同款 C151348）。
- **F1(265,305) SMD1812P200TF16 自恢复保险丝**（2A 保持 / 4A 跳闸 / 16V，F1812，C20812）：`5V_PF` → `5V`（SoC 那一路）
- **F2(120,460) 同型号 C20812**：`5V_PF` → `5V_A`（功放那一路）。分两路的理由：功放 class-D 满功率脉冲会把
  5V 母线瞬时拉低，经 F1 的 20mΩ 和走线耦合到 SoC；分开后功放的电流波动只在自己那段。
  两路用**同一料号**，SMT 不增加上料位/最小包装成本。
- **D1(250,360) SMAJ5.0A 单向 TVS**（SMA/DO-214AC，C143135）：K→`5V`，A→GND
  （原 D1 BAT54SW 中间脚悬空、两只二极管都不成回路，等于没装，2026-10-25 换掉）
- C21(515,240) 22µF 10V X5R（C84419）在 `5V` 上做输入储能；**C22 已于 2026-10-25 删除**（两颗 22µF 冗余，留一颗）。
- **C42/C43（两颗重复的 1µF）已于 2026-10-25 删除**：挂在 5V↔GND，与 C21、C5/C7 重复，且没接在麦克风偏置节点上。
- **C15（10µF/35V）已删除；`BATT_IN` 网络取消**：原 J13-2/J14-2 改为 `SERVO_VPASS` 直通网
  （网表：`SERVO_VPASS` = J13-2 / J14-2），只让舵机电池在 J13↔J14 之间过线，HAT 不从电池取电（舵机电源另做 HUB 板，见 docs/02）。

### ④ 中右：DXL 总线端
- J13(515,1600) / J14(715,1610) A2007 2.0mm 3P 舵机口（C225336）：1=GND、2=`SERVO_VPASS`、3=`DXL_DATA`
- **R35(260,1585) 22Ω ±1%（0603，C23345）**（用户改，原 TH1 100Ω PTC）
- **R33 已删除（2026-10-25）**：`DXL_DATA_INT` 与 `DXL_DATA_CLAMPED` 合并为同一网络
  （网表：`DXL_DATA_CLAMPED` = U7-4 / R32-2 / U6-2 / D4-1 / R35-1；`DXL_DATA` = J13-3 / J14-3 / R35-2）

### ⑤ 右上：codec 时钟与 1V8
- Y1(1460,285) 12MHz 晶振 + C14(1425,345) 100nF；`AUDIO_MCLK` = Y1-3 / U2-1
- R6(1425,220) 10k codec 复位上拉 + C38(1425,390) 100nF：`CODEC_RESET_N` = R6-2 / C38-2 / U2-31
- U3(1235,395) XC6206P182 1V8 LDO（C347373）+ C12(1170,255) 10µF + C26(1280,255) 100nF；
  `1V8` = U3-2 / C12-1 / C26-2 / U2-32(DVDD)
- 3V3 上重复的 10µF **C37 已删除**，只留 C13(1220,335)，靠近 LDO 输入更有用

### ⑥ 右中：codec 本体
- U2(1305,735) TLV320AIC3104IRHBR（C181753），EP=GND
- 去耦（2026-10-25 精简：删掉每域重复的 1µF C29/C31）：
  C27(1130,910) 1µF + C28(1125,980) 100nF、C35(1325,900) 1µF + C36(1695,980) 100nF、
  C30(1315,980) 100nF、C32(1505,980) 100nF
- **R7 0Ω（MIC2L→GND）已删除**，U2-14 的 stub 网络名直接改成 `GND`（0Ω 短接本就是这个效果）。

- 未用：U2-15 MICBIAS（stub 已删，网络消失）、U2-16 MIC2R/LINE2R、U2-19/20/22/23 耳机、U2-28/30 线路输出负极

### ⑦ 右下：功放与麦克风
- U1(1510,1320) PAM8406D 5W 立体声功放（C86270），MODE 接高=Class-D

  删掉 PVDD 上重复的 1µF C4/C6（2026-10-25）

- 右声道：`CODEC_RIGHT_LOP` = U2-29 / C2(1720,1640)-1 → C2 → `AMP_INR_AC` → R2(1720,1560) 10k → `AMP_INR` = U1-10

- 麦克风：J2(2000,1395) 外接左麦、J9(2005,1640) 外接右麦（均 A1251 1.25mm 2P，2 线驻极体）
  - 偏置：R22(2195,1285)/R23(2195,1340) 10k 从 `5V` 分出
  - 耦合：C41(2300,1720) 1µF → `MIC_EXT_L_AC` = C41-1 / U2-10；C40(2290,1790) 1µF → `MIC_EXT_R_AC` = C40-1 / U2-12
  - **偏置去耦：C44(2025,1440) / C45(2025,1700) = 470pF（0603，LCSC C1620）**
    网表实测：`MIC_EXT_L_BIAS` = C41-2 / R22-1 / J2-2 / C44-2；`MIC_EXT_R_BIAS` = C40-2 / R23-1 / J9-2 / C45-2
    （2026-10-25 先按 100nF 加，后经用户确认偏置节点阻抗匹配改为 470pF）
- **左声道已删除（2026-10-25）**：删 C1（1µF 耦合）、R1（10k 输入电阻）、`CODEC_LEFT_LOP` 与
  `AMP_L_P_RAW`/`AMP_L_N_RAW` 的 stub；U1-7(INL) 短接 stub 接 `GND`，U2-27(LEFT_LOP) 与 U1-1/U1-3 悬空

## DRC 状态（2026-10-25，EDA V3.2.149 实测）

- **0 error / 4 warning**。
- 消除的 8 条 error 全是同一类：「元件的引脚与焊盘未对应（引脚没有对应焊盘：1、2）」。
  根因是**用 API 放置的器件只给了 `{libraryUuid, uuid}`**，`getState_Footprint()` 只存了 `uuid`，
  缺 `libraryUuid` 与封装名；用 `eda.lib_Device.search()` 返回的完整 device 条目重建这 11 个器件
  （C8、C9、C44、C45、R12、R13、R35、U11、F1、D1、H1）后全部消失——重建时引脚坐标不变，stub 连线不受影响。
- 剩下 4 条 warning 都是提示性的，不影响出图/打样：
  1. 「元件属性与供应商器件不一致，建议做器件标准化」×2（EDA 把全图器件按批归成两条，含 J4/C21/R26 等 kissqy 原生件）
  2. 「存在悬空引脚，建议加 NC 标记」×2（J4 的 20 个空位、U2 的 9 个不用脚、U1-1/U1-3），
     这些脚设计上就是不接；要做零警告就在 EDA 里逐个打 NC 标记（纯图形标记，不改电气）。
