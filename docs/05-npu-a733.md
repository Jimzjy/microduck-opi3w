# A733 NPU（VIP9000）调研与 duck-detect 后端计划

## 结论

A733 NPU 这条路是通的，作为 duck-detect 的可选加速后端，**不做默认依赖**。

## 事实（已联网核实）

- NPU：Vivante VIP9000（VeriSilicon/芯原架构），3 TOPS，INT8/INT16/FP16/BF16
- 工具链：VeriSilicon **ACUITY Tools**——离线把 ONNX/Caffe/TF/TFLite 转成 NBG 格式，
  板端加载厂商运行时库；与 rknn「转模型 + 板端 dlopen」模式同构
  （参考同款 VIP9000 的 T536 入门指南：cloud.tencent.com/developer/article/2441443）
- 同 SoC 的瑞莎 Cubie A7A 官方支持 Debian/Tina/Buildroot；社区有 Zero 3W 跑 YOLOv5s
  实时推理的说法（CSDN，未实测）

## 不确定（待板子实测）

- Orange Pi Zero 3W 官方镜像是否内置 NPU 驱动（galcore.ko）与用户态运行时 .so
- ACUITY 工具链需从全志 BSP / Cubie A7A 镜像获取，版本匹配未知

## duck-detect 后端设计

上游 `duck-detect/src/rknn.rs` 是 dlopen rknn 运行时 + 固定 trait 接口，编译期不依赖
Rockchip。移植时：

1. duck-detect 默认走 CPU（ONNX Runtime，同一检测模型），零硬件依赖
2. 新增平行后端 `vnn.rs`：dlopen VIP9000 运行时，实现同一 trait
3. 模型用 ACUITY 从同一 ONNX 转 NBG，构建脚本可选开启
